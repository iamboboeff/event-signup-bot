# event-signup-bot

Телеграм-бот записи на мероприятие: выбор города и направления, анкета участника, список записавшихся,
уведомления администраторам о новых заявках и подтверждение оплаты вручную.
Настройки меняются в закрытой веб-админке внутри Telegram, данные хранятся
в папке `data` на сервере без Google Sheets.

Стек: Node.js + [grammy](https://grammy.dev). Работает в двух режимах:
- **long-polling** — если `WEBHOOK_URL` не задан (проще всего для VPS);
- **webhook** — если задан `WEBHOOK_URL`.

## Быстрый старт (локально)

```bash
cp .env.example .env      # вставь BOT_TOKEN, ADMIN_IDS, GROUP_CHAT_ID и т.д.
npm install
npm start
```

Как узнать `GROUP_CHAT_ID` и `ADMIN_IDS`: добавь бота в группу и отправь `/id` —
бот пришлёт нужные id.

Администратор отправляет `/admin`, открывает веб-панель и меняет название,
города, направления, даты, наставников, стоимость и реквизиты. Команда
`/adminoff` возвращает обычный пользовательский режим. Доступ проверяется по
`ADMIN_IDS` и, при необходимости, `ADMIN_USERNAMES`.

Кнопка ⚙ у города, направления или наставника открывает две дополнительные
настройки:

- **Системное сообщение.** Пока текст заполнен, бот показывает его вместо
  продолжения анкеты и закрывает запись на этом варианте — так сделаны «Скоро…»
  и «Запись на мероприятия в Москве откроется позже». Очистили текст — запись
  снова открыта. Ничего править в коде не нужно.
- **Свои даты наставника.** Если переключатель включён, участник видит на шаге
  «Дата» именно этот список; выключен — общий список из карточки «Общие даты».
  Удаление последней своей даты возвращает наставника к общему списку.

Сообщения и даты привязаны к самим вариантам: переименовали или удалили вариант —
его настройки уходят вместе с ним.

В обычном режиме меню Telegram показывает только команду `/start` («Записаться»).
После `/admin` конкретному администратору открывается полное меню команд, а
после `/adminoff` оно снова скрывается. Если открыть адрес панели без активного
админ-режима, страница показывает только заставку doTERRA.

Администраторы могут управлять доступом прямо в личном чате с ботом:

- `/addadmin @username` или `/addadmin 123456789` — добавить администратора;
- `/kickadmin @username` или `/kickadmin 123456789` — удалить администратора.

Серверный список из `ADMIN_IDS`/`ADMIN_USERNAMES` защищён от удаления и служит
резервным доступом. Для постоянных прав рекомендуется использовать Telegram ID:
username пользователь может изменить.

## Переменные окружения

Все описаны в [`.env.example`](.env.example). Ключевые:

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен от @BotFather (обязательно) |
| `ADMIN_IDS` | ID админов через запятую; рекомендуемый способ выдачи доступа |
| `ADMIN_USERNAMES` | Дополнительный список username без `@` через запятую |
| `GROUP_CHAT_ID` | группа для уведомлений о новых записях |
| `ADMIN_WEBAPP_URL` | полный HTTPS-адрес админки; например `https://bot.example.com/admin` |
| `DATA_DIR` | папка постоянных данных; по умолчанию `./data` |
| `WEBHOOK_URL` | публичный URL — включает режим webhook; пусто = long-polling |
| `DOCTOR_SHEET_WEBAPP_URL` | адрес Apps Script тестового расписания врача |
| `DOCTOR_SHEET_SECRET` | общий секрет бота и Apps Script, не короче 16 символов |

`.env`, папка `data` и логи в git не попадают (см. `.gitignore`).

## Развёртывание на Bothost

Рабочий бот подключён к репозиторию `iamboboeff/event-signup-bot`, ветка `main`.
В Bothost задаются `BOT_TOKEN`, `ADMIN_IDS` и `GROUP_CHAT_ID`. Переменную
`WEBHOOK_URL` задавать не нужно: бот работает через long polling.

После подключения домена Bothost автоматически передаёт его в `DOMAIN`, и бот
использует `https://<DOMAIN>/admin` для встроенной админ-панели. Настройки,
заявки и незавершённые анкеты хранятся в `/app/data`.

Для ручного выпуска новой версии нажмите у бота «Обновить из Git». Для
автоматического выпуска добавьте выданный Bothost URL автообновления в Webhooks
репозитория GitHub.

## Тестовая запись на диагностику

Для направления «Диагностика с доктором» бот может брать свободные дату и время
из Google Таблицы. Интеграция включается только при одновременном наличии
`DOCTOR_SHEET_WEBAPP_URL` и `DOCTOR_SHEET_SECRET`; без них прежний сценарий бота
остаётся без изменений.

Код связанного с таблицей API находится в `doctor-schedule-apps-script.gs`.
Секрет задаётся в свойствах Apps Script под именем `DOCTOR_API_SECRET` и тем же
значением добавляется в переменные окружения Bothost. API отдаёт боту только
свободные слоты — имена и другие данные уже записанных пациентов не возвращаются.
При бронировании строка блокируется, повторно проверяется и только затем получает
статус «Занято», имя пациента и выбранного консультанта.

## Развёртывание на сервере (VPS, бесперебойно)

Для самого бота в режиме long-polling публичный URL не нужен. Для встроенной
веб-админки нужен HTTPS-домен, который проксирует запросы на порт бота, и
`ADMIN_WEBAPP_URL=https://ваш-домен/admin`.

Если бот уже работает по webhook на `https://bot.example.com`, отдельно задавать
адрес панели не нужно: автоматически используется `https://bot.example.com/admin`.
Команда `/admin` сама показывает администратору кнопку с этим адресом.

GitHub Pages подходит только для статических HTML/CSS/JS-файлов. Текущей панели
нужен сервер бота для проверки Telegram-доступа, API настроек и хранения данных,
поэтому целиком запускать её на GitHub Pages нельзя. Исходный код может храниться
на GitHub, а работающий бот с панелью должен быть размещён на VPS или другом
сервисе, который запускает Node.js и предоставляет постоянный диск.

```bash
git clone https://github.com/iamboboeff/event-signup-bot.git
cd event-signup-bot
npm install --omit=dev
cp .env.example .env && nano .env   # заполни переменные
```

Держать процесс живым удобнее всего через **systemd**:

```ini
# /etc/systemd/system/event-bot.service
[Unit]
Description=Event signup Telegram bot
After=network-online.target

[Service]
Type=simple
WorkingDirectory=/home/USER/event-signup-bot
ExecStart=/usr/bin/node bot.js
Restart=always
RestartSec=5
EnvironmentFile=/home/USER/event-signup-bot/.env
Environment=DATA_DIR=/home/USER/event-bot-data

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now event-bot
sudo systemctl status event-bot        # проверить
journalctl -u event-bot -f             # смотреть логи
```

После `git pull` обновление применяется через `sudo systemctl restart event-bot`.

Альтернатива — [pm2](https://pm2.keymetrics.io): `pm2 start bot.js --name event-bot && pm2 save && pm2 startup`.

## Файлы

- `bot.js` — сам бот (анкета, список, уведомления, подтверждение оплаты).
- `admin.html` — закрытая веб-панель настроек внутри Telegram.
- `admins.json` — начальный список администраторов для первого запуска.
- `config.json` — исходные настройки для первого запуска (в том числе стартовые
  системные сообщения в `notices` и свои даты наставников в `mentorDates`).
- `doctor-schedule-apps-script.gs` — API тестового расписания врача для Google Таблицы.
- `data/admins.json` — изменяемый список администраторов (создаётся автоматически).
- `data/admin-modes.json` — кто сейчас работает в режиме администратора.
- `data/config.json` — актуальные настройки из админки (создаётся автоматически).
- `data/registrations.json` — заявки (создаётся автоматически).
- `Dockerfile` — контейнер для webhook-режима; папке `data` нужен постоянный диск.
- `server.js` / `index.html` — прототип веб-анкеты (не обязателен для бота).
